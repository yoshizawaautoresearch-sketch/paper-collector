# 論文新着コレクター — セットアップ手順書

経済学・金融の実証分析に関する論文の新着を、**週2回(月曜・木曜の朝)自動で集めて一覧ページにまとめ、メールでお知らせする**仕組みです。
GitHub の無料機能だけで動くため、費用はかかりません。一度設定すれば、あとは届いたメールを開いて一覧を読むだけです。

---

## 全体像

```
 週2回 自動実行(GitHub Actions)
   │  日銀・RIETI・ESRI・金融庁・NEP・NBER・arXiv・OpenAlex・CiNii・主要学術誌 から新着を取得
   │  重複を除き、「日本関連」「計量」の目印を付ける
   ▼
 一覧ページを更新(GitHub Pages) ……… https://<あなたのユーザー名>.github.io/paper-collector/
   │
   ▼
 新着のお知らせ(GitHub Issue) ……… GitHub からメールが届く
```

一覧ページでは、期間・分類・目印(★日本関連×計量 など)で絞り込み、キーワード検索ができます。
各論文の「Claude に要約を頼む文面をコピー」を押してClaudeのチャットに貼り付けると、追加料金なしで要約を頼めます。

## セットアップ(所要30〜60分)

### ステップ1 GitHub アカウントを作る

1. https://github.com/signup を開きます。
2. メールアドレス、パスワード、ユーザー名(英数字。一覧ページのURLに使われます)を入力します。
3. 届いた確認コードを入力して登録を完了します。
4. 2段階認証の設定を求められたら、画面の案内に従って設定してください(スマートフォンの認証アプリかSMS)。

### ステップ2 リポジトリ(保管場所)を作る

1. GitHub 右上の「+」→「New repository」を押します。
2. 次のとおり入力して「Create repository」を押します。
   - Repository name:`paper-collector`
   - **Public** を選ぶ(無料で一覧ページを使うために必要です。APIキーなどの秘密情報は公開されません)
   - その他のチェックは付けない

### ステップ3 ファイルをアップロードする

1. 受け取った `paper-collector.zip` をパソコン上で展開します。
2. 作ったリポジトリの画面で「uploading an existing file」のリンクを押します。
3. 展開したフォルダの**中身すべて**(`collect.py`、`config.toml`、`page_template.html`、`README.md`、`docs`、`data`、`.github`)をドラッグ&ドロップし、下の「Commit changes」を押します。

> **重要:`.github` フォルダが隠れていることがあります。**
> Mac の Finder では `Command + Shift + .`(ピリオド)、Windows のエクスプローラーでは「表示」→「隠しファイル」で表示できます。
> アップロード後、リポジトリに `.github/workflows/collect.yml` があるか確認してください。
> 見当たらない場合は「Add file」→「Create new file」を押し、ファイル名の欄に `.github/workflows/collect.yml` と入力して、
> 同名ファイルの中身をそのまま貼り付けて保存してください。

### ステップ4 自動実行に書き込みを許可する

1. リポジトリの「Settings」→ 左メニュー「Actions」→「General」を開きます。
2. 下の方の「Workflow permissions」で **「Read and write permissions」** を選び、「Save」を押します。

### ステップ5 APIキーを用意して登録する(あとからでも可)

キーがなくても仕組みは動きます(その情報源だけ省略されます)。まずは動かしてから、後日追加しても構いません。

| 名前 | 用途 | 入手方法 |
|---|---|---|
| `OPENALEX_API_KEY` | 日本関連の英語論文の検索 | https://openalex.org でアカウント作成(約30秒)→ https://openalex.org/settings/api に表示されるキーをコピー |
| `CINII_APPID` | 日本語論文の検索 | https://support.nii.ac.jp/ja/cinii/api/developer の案内に従い利用登録(発行まで数日かかることがあります) |
| `CONTACT_EMAIL` | 論文データベースに伝える連絡先(任意) | ご自身のメールアドレス |

登録方法:リポジトリの「Settings」→「Secrets and variables」→「Actions」→「New repository secret」を押し、
**Name** に上の表の名前、**Secret** に値を入れて「Add secret」。3つとも同じ手順です。

### ステップ6 初回を手動で実行する

1. リポジトリの「Actions」タブを開きます(有効化を求められたら「I understand my workflows, go ahead and enable them」を押します)。
2. 左の「論文新着の収集」→ 右の「Run workflow」→ 緑の「Run workflow」を押します。
3. 1〜3分で緑のチェックが付けば成功です。赤い×の場合は「困ったとき」を見てください。

### ステップ7 一覧ページを公開する

1. 「Settings」→ 左メニュー「Pages」を開きます。
2. 「Build and deployment」の Source を **「Deploy from a branch」**、Branch を **`main`**、フォルダを **`/docs`** にして「Save」。
3. 数分後、`https://<ユーザー名>.github.io/paper-collector/` で一覧ページが開けます。スマートフォンのホーム画面に追加しておくと便利です。

### ステップ8 メール通知を確認する

新着があるたびに「論文新着 2026-10-15(○本)」というお知らせ(Issue)が作られ、GitHub から登録メールアドレスに届きます。
メールには「★日本関連×計量」と分類ごとの主な論文、一覧ページへのリンクが入っています。

届かない場合:右上のアイコン →「Settings」→「Notifications」で、「Watching」の **Email** にチェックが入っているか確認してください。

## 日々の使い方

- **届いたメールを開く** → 気になる論文はリンクから原文へ。全体は一覧ページで。
- **一覧ページ** → 「最新の取得分」「★ 日本関連 × 計量」で絞ると、まず読むべきものが見つかります。
- **要約がほしいとき** → 論文の「Claude に要約を頼む文面をコピー」を押し、Claude のチャットに貼り付けます。

## 設定を変えたいとき

設定はすべて `config.toml` にまとまっています。GitHub 上でファイルを開き、鉛筆マーク(Edit)で編集して「Commit changes」を押すだけで、次回の実行から反映されます。

- **情報源を止める**:その情報源の `enabled = true` を `enabled = false` に。
- **CiNii の検索語を変える・増やす**:`[[cinii]]` のブロックをコピーして `name` と `q` を書き換え。
- **学術誌を追加する**:`[[journal]]` のブロックをコピーして雑誌名と ISSN を書き換え。
- **「日本関連」「計量」の判定語を調整する**:`[flags]` の各パターンに語を `|` 区切りで追加。
- **実行日時を変える**:`.github/workflows/collect.yml` の `cron` の行(時刻は世界標準時。日本時間から9時間引いた値)。

迷ったら、変えたい内容を Claude に伝えれば書き換え案を作ります。

## 困ったとき

| 症状 | 対処 |
|---|---|
| Actions が赤い×で失敗する | 失敗した実行を開き、赤い行のメッセージを Claude に貼り付けて相談してください。 |
| 「Permission denied」「403」で保存に失敗 | ステップ4の「Read and write permissions」を確認。 |
| 一覧ページの「取得できなかった情報源」に表示がある | 一時的な障害なら次回自動で回復します。毎回同じ情報源が失敗する場合は URL 変更の可能性があるので Claude に相談を。 |
| CiNii が「未設定のため省略」 | ステップ5の `CINII_APPID` が未登録です(登録すれば次回から取得されます)。 |
| 自動実行が止まった | GitHub は長期間動きのないリポジトリの定期実行を止めることがあります。Actions 画面で再度有効化してください(この仕組みは毎回結果を保存するため、通常は止まりません)。 |
| 仕組みを止めたい | 「Actions」→「論文新着の収集」→ 右上「…」→「Disable workflow」。 |

## 注意事項

- SSRN と Google Scholar は利用規約で自動取得が禁止されているため、この仕組みには含めていません。必要な場合は各サービスのメールアラートを別途ご利用ください。
- arXiv(3秒に1回)、OpenAlex、Crossref、CiNii の利用ルールに沿った間隔で取得しています。
- 「日本関連」「計量」の目印はキーワードと著者所属による自動判定です。取りこぼしや誤判定があり得ます。
- 一覧ページには直近90日分を残します(`config.toml` の `keep_days` で変更できます)。

## 公開範囲について

- 一覧ページとリポジトリは、URLを知っていれば誰でも見られる状態です(GitHub の無料プランの仕様)。
- 一覧ページには「検索エンジンに表示しない」指定を入れてあるため、Google 等の検索結果には通常出てきません。
  ただし、検索エンジン側がこの指定に従うことを前提とした仕組みで、アクセスそのものを制限するものではありません。
- 見えるもの:論文のタイトル・著者・抄録(いずれも元から公開情報)、`config.toml` の情報源とキーワード、GitHub のユーザー名、新着お知らせ(Issue)。
- 見えないもの:Secrets に登録した APIキー・連絡先メール。
- 将来、完全に非公開にしたくなった場合は、リポジトリを Private に切り替えてお知らせメールで受け取る形に変更できます(Claude に相談してください)。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `config.toml` | 情報源・判定語などの設定(ここだけ触ればOK) |
| `collect.py` | 収集プログラム本体(Python 標準機能のみで動作) |
| `page_template.html` | 一覧ページのひな形 |
| `.github/workflows/collect.yml` | 自動実行のスケジュールと手順 |
| `docs/index.html` | 生成される一覧ページ(自動更新) |
| `data/papers.json` | 収集済み論文の記録(自動更新・重複判定に使用) |
